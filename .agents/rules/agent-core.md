# Правила работы агента с локальным CLE

> Эти правила относятся к **локальному движку CLE**. Корневой [AGENTS.md](../../AGENTS.md), README, штатные средства GitHub/CI и явное разрешение владельца управляют операциями над репозиторием и инфраструктурой. CLE не является универсальным executor для production.

1. **Правильный инструмент вместо принудительного CLE для всего:**
   - Повторно используемые локальные функции CLI оформляй через `python manage.py <command>` / `cle <command>`, соблюдая [регламент команд](cle-command-authoring.md).
   - Для ревью кода, тестирования, GitHub, CI, документации и аналитики используй соответствующий разрешённый инструмент. Не отправляй внешние действия в `cle exec` только ради правила «одна точка входа».
   - Не создавай случайные служебные файлы при наличии существующей команды; это **не запрещает** необходимые изолированные тесты и исследование исходников.

2. **Экономия контекста без подмены доказательств:**
   - Предпочитай компактный `--json` и точечные логи, но не считай вывод одной команды доказательством правильности, безопасности или релиза.
   - Если задача требует ревью реализации, диагностики, защиты данных или оценки последствий, **читай соответствующие исходники и diff**. «Один вопрос = один CLI вызов» — полезная эвристика, не запрет на проверки.

3. **Точечная процедурная память:**
   - При необходимости читай `.agents/skills/agent-cli/gotchas.md`; подтверждённые повторяемые ошибки записывай по `.agents/rules/self-learning.md`, без ключей, паролей и приватных данных.
   - Не обновляй журналы рефлексии для каждой тривиальной операции без новой полезной находки.

4. **Границы исполнения и безопасности:**
   - `cle exec` запускает **произвольный Python с правами текущего пользователя**. Timeout, `--dry-run` (если применим) и Target Host Guard не изолируют файловую систему, сеть, секреты или полномочия. Запускай только доверенный локальный код.
   - Dev/Production разделены: CI и локальные проверки не должны менять production. Для деплоя, секретов, системных служб, удаления данных, веток и изменений GitHub Settings требуется отдельное явное owner GO.
   - До merge/релиза фиксируй exact SHA, реальные тесты и неизвестные ограничения. Статусы `NOT_RUN` и `UNKNOWN` лучше выдуманного PASS.
