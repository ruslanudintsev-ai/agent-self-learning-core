# Участие в разработке Agent Self-Learning Core

Это публичный инструментарий для локальных AI-агентов. Цель изменений — проверяемые улучшения без обхода системных ограничений и неожиданных действий на машине пользователя.

## Перед кодом

- Изучите [README.md](README.md), [AGENTS.md](AGENTS.md) и соответствующие файлы `.agents/rules/`.
- Проверьте существующие GitHub Issues/PR. Для новой самостоятельной задачи создайте Issue с критериями готовности, воспроизведением ошибки или конкретным предлагаемым результатом.
- Работайте в отдельной ветке от актуального `main`; не меняйте чужой незавершённый PR без согласования. Публикуйте узкий Draft PR и связывайте его с Issue через `Refs #N`.

## Изменения команд CLE

Команды расположены в `core/commands/`. Для новой команды сначала прочтите [регламент](.agents/rules/cle-command-authoring.md), реализуйте контракт, добавьте тесты и обновите документацию команд.

Для локальной проверки, если установлен Python и зависимости разработки:

```bash
python -m pytest tests -q
python manage.py sys-info --help
```

Для новой CLE-команды используйте описанные в проектном регламенте `dev-validate`, проверку `--help` и `--json`. Команды выше — **инструкция, а не заявление об уже выполненных тестах**.

Отчёт PR должен содержать команду проверки, результат/exit code, точный Git SHA и ограничения среды. Если проверка не выполнялась, пишите `NOT_RUN`, а не `PASS`.

## Безопасность и публикации

- `cle exec` запускает код с правами текущего процесса; он не является sandbox. Не запускайте недоверенные программы и не используйте его для выполнения команд на production.
- Не добавляйте в Issue, PR и коммиты секреты, приватные конфигурации, персональные сведения и необработанные диагностические журналы.
- Не добавляйте CI с доступом к приватным self-hosted runners для непроверенного кода из forks.
- Не меняйте настройку репозитория, release, инфраструктуру и `main` без отдельного разрешения владельца.
- Сохраняйте совместимость публичного CLI: breaking changes требуют отдельного обоснования и проверки.

Перед слиянием проверьте diff, статус тестов и документацию. **Merge и публикация выполняются только после явного owner GO.**
